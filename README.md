# 全国観光謎アプリ（仮称）

**全国の謎を、実際に訪れるきっかけにする。**

自治体の担当者が観光スポットを出題し、旅行者は全国共通の地図から謎を選びます。指定された撮影範囲まで足を運び、対象を写真に撮って回答します。クリアした写真と初回クリア日が本人の記録に残ります。

## 現在の状態

2026-11-05時点で、**ローカルで起動できる最小Webアプリ**を用意しました。React・TypeScript・Viteを使い、地図のデザインプレビューから架空のサンプル問題を選べます。Googleログイン・ログアウト・状態復元に対応し、[撮影と写真確認の画面](docs/camera-preview.md)では、撮影時のGPS情報と写真を画面内だけで保持します。[旅行者向けUIの範囲](docs/traveler-ui.md)も確認してください。Google Maps接続・写真とGPSの送信・判定・記録保存は未実装です。実機でのGPS取得は未検証です。

設定なしでも匿名で起動・閲覧できます。Googleログインを使うときだけ、[Firebase接続手順](docs/firebase-auth.md)に従って`.env.local`を設定します。クラウド設定・デプロイ・公開URLはこの実装に含みません。運営の提出案内はこのREADMEの後半にそのまま残しています。GitHub Actions / Pagesには依存しません。

## まず起動する

D担当の[素材登録・下書き編集・表示確認デモ（A03〜A05）](docs/admin-demo.md)は、開発サーバー起動後に `/admin-demo` で開きます。未認証の架空データ用フォームで、入力・参考写真は画面内だけに保持し、アップロード・保存・AI・公開処理には接続しません。

Node **26.7.0** / npm **11.19.0**を使います。異なる版ではインストールを止め、4人の環境の違いを見つけやすくしています。

このリポジトリのフォルダ（`package.json`がある場所）で実行します。

```sh
npm ci
npm run dev
```

[起動画面を開く](http://localhost:5173/) →「問題を見てみる」で架空の問題を確認できます。終了はターミナルで **Ctrl+C**。`npm ci`は、記録された同じ版の部品を揃えるコマンドです。

全員が変更後に行う確認は次の1つです。型検査・静的検査・画面テスト・ビルドを順に実行します。

```sh
npm run check
```

取得方法、未マージのPRを試す方法、困ったときの対処は[共同開発ガイド](docs/development.md)へ進んでください。

A担当の[共通データとAPI呼び出し口](docs/api.md#8-最初の共通api実装)に加え、別パッケージとして[ローカルAPIの土台](server/README.md)を追加しました。[開発用の接続手順](docs/local-api.md)で、画面から架空の1問を取得し、Googleログインをサーバーでも確認できます。写真判定と保存はまだありません。既定の画面内プレビューはAPIへ通信しません。

## A担当のローカルAPIを試す

実在しない地域・問題だけを返す開発用サーバーです。Firebase未設定でも公開GETを確認できます。認証確認の`GET /api/v1/session`は、設定なしなら503を返します。起動手順・認証の設定・制限は[server/README.md](server/README.md)、契約は[APIの実装範囲](docs/api.md#9-ローカルapiの土台)を確認してください。

```sh
npm --prefix server ci --ignore-scripts
QUEST_DATA_MODE=demo NODE_ENV=development npm --prefix server run dev
```

`http://127.0.0.1:8787/health`で起動を確認できます。データは常に架空のデモで、本番起動は拒否します。終了は **Ctrl+C**。クラウドへのデプロイやDB作成は行いません。

認証後に利用者・問題・版を結び付ける[挑戦開始API](docs/challenge-start.md)も追加しました。`local-api`モードでは「挑戦を始める」で開始を確認してから撮影画面を開きます。開発用の一時管理で、再起動すると消えます。写真送信・保存は未実装です。

Webとサーバーは別々に検証します。ルートのテスト対象は`src/`、サーバーは`server/test/`です。

```sh
npm run check
npm --prefix server run check
```

## 固定する製品の軸

- 全国地図を入口にし、自治体別の参加アプリや固定コースに分断しない。
- 地図・問題・ヒントはログイン不要。挑戦を開始するときにGoogleログインする。
- 指定撮影範囲内の位置情報と対象の写真をサーバーで確認してクリアする。
- 正確な対象位置・参考全景写真を通常の未クリア用データに含めない。
- 登録・出題は確認された自治体担当者のみ。旅行者の投稿解放はない。
- 天候機能、ランキング、再訪履歴、構図の完全再現は初期版の対象外。

## 開発の始め方

1. 上記資料と現在の実装を読む。React・TypeScript・Viteは今回の土台の実装判断です。残るクラウド等の提案を採用済みと混同しない。
2. 全員がこの土台を取得して起動し、Issueまたはチームの連絡で担当を共有する。
3. 土台の取り込み後は、最新の`main`から短い作業ブランチを作る。未取り込みの段階で独自のアプリ一式を生成しない。
4. 次の実装で「地図で1問選ぶ→Googleログイン→写真回答→本人の記録」の一周を小さく積み上げる。
5. 変更範囲、実行した検証、未検証部分をPRに書き、別の1人が確認して取り込む。

## 公開リポジトリの注意

実写真、個人の行動履歴、回答画像、正解データ、秘密のAPIキー、サービスアカウント鍵、クレジット引換コードはGitへ入れません。実在地点の正解データは公開コードと分離し、ローカルのダミーデータは架空・デモであると明示します。公開キー設定と秘密情報の区別は[技術設計](docs/architecture.md)を参照してください。

  ## 開発用のリポジトリは別に作ることをおすすめします

  このリポジトリでは **GitHub Actions と GitHub Pages が使えません**。CI やデプロイ、Pages での公開をしたいときは、チームで開発用のリポジトリを別に作ってください。

  - 開発用のリポジトリは、チームのメンバーのアカウントや、チームで作った Organization に作ってください

  ## 秘密情報をコミットしない

  API キー・パスワード・サービスアカウントの鍵などは、**絶対にコミットしないでください**。公開リポジトリなので、push
  した時点で誰でも見られます。開発用のリポジトリから持ってくるときも、履歴ごと push すると、過去のコミットに含まれる秘密情報も公開されます。

  - 秘密情報は `.env` や `.dev.vars` などに書き、コミットしない（`.gitignore` に入れてあります）
  - 誤って push したら、すぐにキー（鍵）を無効にして作り直し、運営に連絡してください。履歴から消すだけでは不十分です
  - GitHub の push protection が、よく知られた形式のキーの push を止めることがあります。止められたら、そのキーをコミットから外してください
