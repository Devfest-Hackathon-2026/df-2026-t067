# 全国観光謎アプリ（仮称）

**全国の謎を、実際に訪れるきっかけにする。**

自治体の担当者が観光スポットを出題し、旅行者は全国共通の地図から謎を選びます。指定された撮影範囲まで足を運び、対象を写真に撮って回答します。クリアした写真と初回クリア日が本人の記録に残ります。

## 現在の状態

React・TypeScript・Viteの開発画面で、架空の問題一覧・詳細・地域名をローカルAPIから取得します。閲覧は匿名で行えます。Googleログイン後は、挑戦開始、写真と位置の開発用送信、受付状態の確認を試せます。全国地図の表示にはGoogle Maps JavaScript APIの設定が必要です。[旅行者向けUI](docs/traveler-ui.md)・[Maps設定](docs/google-maps.md)

| 担当 | ローカルで試せる操作 |
|---|---|
| B | 問題一覧・詳細、通常ヒントと公開ヒント画像、ログイン後の問題報告。[開発用の問題報告](docs/api.md#20-開発用の問題報告) |
| C | 写真・位置の送信と受付照会、合成記録の本人一覧・写真・削除。[回答送信](docs/camera-preview.md#ローカルapiで回答を送る)・[合成記録](docs/owner-discoveries.md#合成記録で一覧写真削除を試す) |
| D | 開発サーバーの `/admin-local` で、所属確認後に下書き・素材・撮影範囲・合成試験・公開・休止・報告を操作。[管理画面の起動と操作](docs/admin-demo.md#開発用の所属問題報告を閲覧する) |

永続APIは別のローカルモードで起動でき、合成素材で回答からクリア・本人記録までをFirestoreエミュレーターとGCS代替サーバーで確認できます。実際の旅行者の写真照合、実データへの接続、自治体権限、本番公開は残件です。[永続APIの起動](server/README.md#永続apiをローカルで起動する)

設定なしでも匿名で起動・閲覧できます。Googleログインを使うときだけ、[Firebase接続手順](docs/firebase-auth.md)に従って`.env.local`を設定します。共有用の開発プレビューを **[https://tour-513804.web.app/](https://tour-513804.web.app/)** で公開しています。URLを開くだけで閲覧でき、閲覧にログインは不要です。更新方法と公開範囲は [Firebase Hostingの手順](docs/hosting.md) を参照してください。運営の提出案内はこのREADMEの後半にそのまま残しています。GitHub Actions / Pagesには依存しません。

## まず起動する

D担当の[素材登録・下書き編集・表示確認デモ（A03〜A05）](docs/admin-demo.md)は、開発サーバー起動後に `/admin-demo` で開きます。未認証の架空データ用フォームで、入力・参考写真は画面内だけに保持し、アップロード・保存・AI・公開処理には接続しません。

Node **26.7.0** / npm **11.19.0**を使います。異なる版ではインストールを止め、4人の環境の違いを見つけやすくしています。

このリポジトリのフォルダ（`package.json`がある場所）で実行します。

```sh
npm ci
npm run dev
```

[下記のローカルAPI](#a担当のローカルapiを試す)も別ターミナルで起動し、[起動画面を開く](http://localhost:5173/) → 問題を選択 →「問題を見てみる」で詳細を確認できます。API停止時は取得失敗と再試行を表示します。終了は各ターミナルで **Ctrl+C**。`npm ci`は、記録された同じ版の部品を揃えるコマンドです。

全員が変更後に行う確認は次の1つです。型検査・静的検査・画面テスト・ビルドを順に実行します。

```sh
npm run check
```

ビルド後の画面は`npm run preview`で起動し、[プレビュー](http://localhost:4173/)を開きます。本番ビルドは既存Hostingと同じ静的プレビューを維持し、ローカルAPIの問題一覧・地域絞り込みは`npm run dev`で確認します。API転送はローカル確認用で、外部へのデプロイ設定ではありません。

取得方法、未マージのPRを試す方法、困ったときの対処は[共同開発ガイド](docs/development.md)へ進んでください。

`npm run dev` の `/` は追加の画面モード設定なしでローカルAPIへ接続します。APIが利用できない場合は再試行を案内します。公開問題が取得できない間も「自分の記録」を開けます。[画面とローカルAPIの接続](docs/local-api.md)

## A担当のローカルAPIを試す

実在しない地域・問題だけを返す開発用サーバーです。Firebase未設定でも公開GETを確認できます。認証確認の`GET /api/v1/session`は、設定なしなら503を返します。起動手順・認証の設定・制限は[server/README.md](server/README.md)、契約は[APIの実装範囲](docs/api.md#9-ローカルapiの土台)を確認してください。

```sh
npm --prefix server ci --ignore-scripts
QUEST_DATA_MODE=demo NODE_ENV=development npm run dev:api
```

PowerShellでは2行目の代わりに次を実行します。`dev:api` はルートの `.env.local` を読み込みます。

```powershell
$env:QUEST_DATA_MODE = 'demo'
$env:NODE_ENV = 'development'
npm run dev:api
```

`http://127.0.0.1:8787/health`で起動を確認できます。データは常に架空のデモで、本番起動は拒否します。終了は **Ctrl+C**。クラウドへのデプロイやDB作成は行いません。

「挑戦を始める」で利用者・問題・版を結び付け、サーバーの開始確認後に撮影画面を開きます。挑戦と受付は再起動で消えます。[挑戦開始API](docs/challenge-start.md)

「写真と位置をデモ送信」で写真と撮影情報を検査し、同じ回答の再送を同じ受付として扱います。`QUEST_LOCATION_MODE=demo` を指定すると範囲外と位置不確実を区別します。範囲内では受付済み（`RECEIVED`）を表示します。[回答受付・本人照会](docs/answer-intake.md)・[GPS demoモード](docs/gps-validation.md)

回答画像の実デコード・EXIF除去と写真照合の呼び出し部品を用意しました。Vertexの実通信・永続回数制限を試す合成画像専用CLIは、通常起動の回答処理と別に利用できます。[画像処理](docs/photo-match.md)・[Vertex試験](docs/vertex-trial.md)

Webとサーバーは別々に検証します。ルートのテスト対象は`src/`、サーバーは`server/test/`です。

```sh
npm run check
npm --prefix server run check
```

## 固定する製品の軸

- 全国地図を入口にし、自治体別の参加アプリや固定コースに分断しない。
- 地図・問題・ヒントはログイン不要。挑戦を開始するときにGoogleログインする。
- 指定撮影範囲内の位置情報と対象の写真をサーバーで確認してクリアする。
- 正確な対象位置・参考全景写真を通常の未クリア用データに含めない。
- 登録・出題は確認された自治体担当者のみ。旅行者の投稿解放はない。
- 天候機能、ランキング、再訪履歴、構図の完全再現は初期版の対象外。

## 開発の始め方

1. 上記資料と現在の実装を読む。React・TypeScript・Viteは今回の土台の実装判断です。残るクラウド等の提案を採用済みと混同しない。
2. 全員がこの土台を取得して起動し、Issueまたはチームの連絡で担当を共有する。
3. 土台の取り込み後は、最新の`main`から短い作業ブランチを作る。未取り込みの段階で独自のアプリ一式を生成しない。
4. 次の実装で「地図で1問選ぶ→Googleログイン→写真回答→本人の記録」の一周を小さく積み上げる。
5. 変更範囲、実行した検証、未検証部分をPRに書き、別の1人が確認して取り込む。

## 公開リポジトリの注意

実写真、個人の行動履歴、回答画像、正解データ、秘密のAPIキー、サービスアカウント鍵、クレジット引換コードはGitへ入れません。実在地点の正解データは公開コードと分離し、ローカルのダミーデータは架空・デモであると明示します。公開キー設定と秘密情報の区別は[技術設計](docs/architecture.md)を参照してください。

# DevFest Hackathon 2026 提出用リポジトリ

  DevFest Hackathon 2026 のチームの **最終提出用** リポジトリです。提出期限までに、作品のコードと資料をこのリポジトリに置いてください。

  ## はじめに

  1. GitHub から届いた招待を受け入れてください（招待の期限は 7 日です）
  2. このリポジトリを clone して、提出物を置いてください

  招待の期限が切れたときや、メンバーが変わったときは、運営に連絡してください。

  ## 開発用のリポジトリは別に作ることをおすすめします

  このリポジトリでは **GitHub Actions と GitHub Pages が使えません**。CI やデプロイ、Pages での公開をしたいときは、チームで開発用のリポジトリを別に作ってください。

  - 開発用のリポジトリは、チームのメンバーのアカウントや、チームで作った Organization に作ってください
  - 開発はそちらで進めて、提出期限までに最終版のコードと資料をこのリポジトリに push してください
  - 審査はこのリポジトリの内容で行います。開発用のリポジトリにしかないものは、審査の対象になりません
  - デプロイした作品の URL があれば、この README に書いてください

  ## 秘密情報をコミットしない

  API キー・パスワード・サービスアカウントの鍵などは、**絶対にコミットしないでください**。公開リポジトリなので、push
  した時点で誰でも見られます。開発用のリポジトリから持ってくるときも、履歴ごと push すると、過去のコミットに含まれる秘密情報も公開されます。

  - 秘密情報は `.env` や `.dev.vars` などに書き、コミットしない（`.gitignore` に入れてあります）
  - 誤って push したら、すぐにキー（鍵）を無効にして作り直し、運営に連絡してください。履歴から消すだけでは不十分です
  - GitHub の push protection が、よく知られた形式のキーの push を止めることがあります。止められたら、そのキーをコミットから外してください
