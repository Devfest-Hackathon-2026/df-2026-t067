# 全国観光謎アプリ（仮称）

**全国の謎を、実際に訪れるきっかけにする。**

自治体の担当者が観光スポットを題材に謎を作ります。旅行者は全国共通の地図から謎を選び、指定の撮影範囲で対象を撮って回答します。クリア時の写真と初回クリア日が本人の記録に残ります。

## 現在の状態

React・TypeScript・Viteの開発画面では、ローカルAPIから架空の問題と地域名を取得します。問題一覧と詳細はログインせずに見られます。Googleログイン後は、挑戦を始め、開発用のAPIに写真と位置を送って受付状態を確認できます。全国地図を表示するにはGoogle Maps JavaScript APIの設定が必要です。[旅行者向けUI](docs/traveler-ui.md)・[Maps設定](docs/google-maps.md)

| 担当 | ローカルで試せる操作 |
|---|---|
| B | 問題一覧・詳細、通常ヒントと公開ヒント画像、ログイン後の問題報告。[開発用の問題報告](docs/api.md#20-開発用の問題報告) |
| C | 写真・位置の送信と受付照会、合成記録の本人一覧・写真・削除。[回答送信](docs/camera-preview.md#ローカルapiで回答を送る)・[合成記録](docs/owner-discoveries.md#合成記録で一覧写真削除を試す) |
| D | 開発サーバーの `/admin-local` で、所属確認後に下書き・素材・撮影範囲・合成試験・公開・休止・報告を操作。[管理画面の起動と操作](docs/admin-demo.md#開発用の所属問題報告を閲覧する) |

永続APIを試すときは、別のローカルモードで起動します。FirestoreエミュレーターとGCS代替サーバーを使い、合成素材で回答を送ってから、クリアと本人記録を確認するところまで試せます。実際の旅行者の写真照合、実データへの接続、自治体権限、本番公開は今後の作業です。[永続APIの起動](server/README.md#永続apiをローカルで起動する)

Firebaseを設定しなくても、開発画面を起動して問題を閲覧できます。Googleログインを使うときだけ、[Firebase接続手順](docs/firebase-auth.md)に沿って`.env.local`を設定します。

[共有用の開発プレビュー](https://tour-513804.web.app/)はログインせずに閲覧できます。更新方法と公開範囲は[Firebase Hostingの手順](docs/hosting.md)を参照してください。運営の提出案内はこのREADMEの後半に原文を掲載しています。このリポジトリはGitHub Actions / Pagesに依存しません。

## まず起動する

D担当の[素材登録・下書き編集・表示確認デモ（A03〜A05）](docs/admin-demo.md)は、開発サーバーを起動して `/admin-demo` を開くと試せます。ログインせずに架空データを使うフォームです。入力内容と参考写真は画面内だけに保持します。アップロード・保存・AI・公開処理には接続しません。

Node **26.7.0** / npm **11.19.0**を使います。4人の環境を揃えるため、別の版を使うとインストールが止まります。

このリポジトリのフォルダ（`package.json`がある場所）で実行します。

```sh
npm ci
npm run dev
```

`npm ci`は、ロックファイルに記録した版の依存パッケージをインストールします。

[ローカルAPI](#a担当のローカルapiを試す)も別のターミナルで起動してください。[起動画面](http://localhost:5173/)で問題を選び、「問題を見てみる」を押すと詳細を確認できます。APIが停止しているときは、取得できなかったことと再試行の方法を表示します。終了するには、各ターミナルで **Ctrl+C** を押してください。

変更後の確認には、全員が次のコマンド1つを使います。型検査、静的検査、画面テスト、ビルドを順に実行します。

```sh
npm run check
```

ビルド後の画面を確認するには、`npm run preview`を実行して[プレビュー](http://localhost:4173/)を開いてください。本番ビルドは既存Hostingと同じ静的プレビューを表示します。ローカルAPIから取得する問題一覧と地域の絞り込みは、`npm run dev`で確認してください。API転送はローカルでの確認に限ります。

取得方法、未マージのPRを試す方法、困ったときの対処は[共同開発ガイド](docs/development.md)へ進んでください。

`npm run dev` の `/` は追加の画面モード設定なしでローカルAPIへ接続します。APIが利用できない場合は再試行を案内します。公開問題が取得できない間も「自分の記録」を開けます。[画面とローカルAPIの接続](docs/local-api.md)

## A担当のローカルAPIを試す

実在しない地域と問題を返す開発用サーバーです。Firebaseを設定しなくても公開GETを確認できます。認証を確認する`GET /api/v1/session`は、Firebaseの設定がないと503を返します。起動手順、認証設定、制限は[server/README.md](server/README.md)を、APIの契約は[APIの実装範囲](docs/api.md#9-ローカルapiの土台)を参照してください。

```sh
npm --prefix server ci --ignore-scripts
QUEST_DATA_MODE=demo NODE_ENV=development npm run dev:api
```

PowerShellでは2行目の代わりに次を実行します。`dev:api` はルートの `.env.local` を読み込みます。

```powershell
$env:QUEST_DATA_MODE = 'demo'
$env:NODE_ENV = 'development'
npm run dev:api
```

`http://127.0.0.1:8787/health`を開くと、サーバーが起動したことを確認できます。サーバーは常に架空のデモデータを返し、本番モードでの起動を拒否します。終了するには **Ctrl+C** を押してください。この手順で使うのはローカル環境だけで、クラウドへのデプロイやDBの作成は不要です。

「挑戦を始める」を押すと、サーバーが利用者と問題の版を結び付けます。開始が確認できると撮影画面が開きます。挑戦と受付のデータは、サーバーを再起動すると消えます。[挑戦開始API](docs/challenge-start.md)

「写真と位置をデモ送信」を押すと、サーバーが写真と撮影情報を検査します。同じ回答を再送したときは、同じ受付を返します。`QUEST_LOCATION_MODE=demo` を指定した場合は、撮影範囲外と、位置を確かめられない場合を区別します。位置が範囲内なら受付済み（`RECEIVED`）を表示します。[回答受付・本人照会](docs/answer-intake.md)・[GPS demoモード](docs/gps-validation.md)

回答画像をデコードしてEXIFを除去する処理と、写真照合を呼び出す処理も用意しています。[画像検証と写真照合](docs/photo-match.md)

通常起動の回答処理とは別に、合成画像専用CLIを使えます。CLIではVertexへの実通信と、再起動しても維持される回数制限を試せます。[Vertex試験](docs/vertex-trial.md)

Webとサーバーは別々に検証します。ルートのテスト対象は`src/`、サーバーは`server/test/`です。

```sh
npm run check
npm --prefix server run check
```

## 固定する製品の軸

- 全国地図を入口にし、自治体別の参加アプリや固定コースに分断しない。
- 地図・問題・ヒントはログイン不要。挑戦を開始するときにGoogleログインする。
- 指定撮影範囲内の位置情報と対象の写真をサーバーで確認してクリアする。
- 正確な対象位置・参考全景写真を通常の未クリア用データに含めない。
- 登録・出題は確認された自治体担当者のみ。旅行者の投稿解放はない。
- 天候機能、ランキング、再訪履歴、構図の完全再現は初期版の対象外。

## 開発の始め方

1. 上記の資料と現在の実装を読む。React・TypeScript・Viteは画面の土台に採用済み。クラウドなどの提案は、決定事項と区別して確認する。
2. 全員がこの土台を取得して起動し、Issueまたはチームの連絡で担当を共有する。
3. 土台を取り込んだら、最新の`main`から短い作業ブランチを作る。取り込む前に別のアプリ一式を生成しない。
4. 地図から1問を選び、Googleログインして写真で回答し、本人の記録を確認する流れを段階的に実装する。
5. 変更範囲、実行した検証、未検証部分をPRに書き、別の1人が確認して取り込む。

## 公開リポジトリの注意

実写真、個人の行動履歴、回答画像、正解データ、秘密のAPIキー、サービスアカウント鍵、クレジット引換コードはGitへ入れません。実在地点の正解データは公開コードと分けて管理します。ローカルのダミーデータには、架空のデモであることを明記します。公開キーの設定と秘密情報の扱いは[技術設計](docs/architecture.md)を参照してください。

  DevFest Hackathon 2026 のチームの **最終提出用** リポジトリです。提出期限までに、作品のコードと資料をこのリポジトリに置いてください。

  ## はじめに

  1. GitHub から届いた招待を受け入れてください（招待の期限は 7 日です）
  2. このリポジトリを clone して、提出物を置いてください

  招待の期限が切れたときや、メンバーが変わったときは、運営に連絡してください。

  ## 開発用のリポジトリは別に作ることをおすすめします

  このリポジトリでは **GitHub Actions と GitHub Pages が使えません**。CI やデプロイ、Pages での公開をしたいときは、チームで開発用のリポジトリを別に作ってください。

  - 開発用のリポジトリは、チームのメンバーのアカウントや、チームで作った Organization に作ってください
  - 開発はそちらで進めて、提出期限までに最終版のコードと資料をこのリポジトリに push してください
  - 審査はこのリポジトリの内容で行います。開発用のリポジトリにしかないものは、審査の対象になりません
  - デプロイした作品の URL があれば、この README に書いてください

  ## 秘密情報をコミットしない

  API キー・パスワード・サービスアカウントの鍵などは、**絶対にコミットしないでください**。公開リポジトリなので、push
  した時点で誰でも見られます。開発用のリポジトリから持ってくるときも、履歴ごと push すると、過去のコミットに含まれる秘密情報も公開されます。

  - 秘密情報は `.env` や `.dev.vars` などに書き、コミットしない（`.gitignore` に入れてあります）
  - 誤って push したら、すぐにキー（鍵）を無効にして作り直し、運営に連絡してください。履歴から消すだけでは不十分です
  - GitHub の push protection が、よく知られた形式のキーの push を止めることがあります。止められたら、そのキーをコミットから外してください
