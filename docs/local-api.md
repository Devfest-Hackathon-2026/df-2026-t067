# 画面とローカルAPIを接続する

開発画面はローカルAPIから架空の問題一覧・詳細・地域名を取得し、Googleログイン後のID tokenをサーバーで確認する。実Mapsの設定は[Mapsガイド](google-maps.md)を参照する。

## モードを選ぶ

| 起動方法 | 動作 |
|---|---|
| `npm run dev` の `/` | ローカルAPIを使う。`VITE_QUEST_DATA_SOURCE`の指定は不要 |
| `npm run dev` の `/admin-local` | 開発用の管理画面。Googleログインと開発用の所属設定が必要 |
| `npm run build` → `npm run preview` | 既存の画面内サンプルを表示。公開問題の取得は行わない |

旅行者画面はAPIのデモモードを検証する。固定のサンプルマーカーは開発用API画面では表示しない。

`npm run build`の成果物を`npm run preview`で確認する場合は、先に`VITE_QUEST_DATA_SOURCE=preview`へ戻してビルドする。実APIを一般公開するためのモードや配信設定は、この段階では追加していない。

## 2つのターミナルで起動する

Googleログインも試す場合は[認証ガイド](firebase-auth.md)の6項目を設定する。サーバーの`FIREBASE_PROJECT_ID`には、ブラウザ側と**同じプロジェクトのID**を指定する。サービスアカウント鍵は不要。

公開問題だけを見る場合は、`FIREBASE_PROJECT_ID`の行を省略する。空文字を指定すると、サーバーは不正な設定として起動を止める。

実設定はルートの`.env.local`に置き、Gitへ追加しない。

ターミナル1（リポジトリのルート）：

```sh
npm ci
npm --prefix server ci --ignore-scripts
QUEST_DATA_MODE=demo NODE_ENV=development npm run dev:api
```

`dev:api`はサーバーをビルドし、127.0.0.1:8787で起動する。Nodeの`--env-file-if-exists=.env.local`でリポジトリのルートにある実設定を読み込む。デモの指定がない場合、本番モードを選んだ場合、Auth Emulatorを設定した場合は起動を拒否する。シェルで設定済みの環境変数は`.env.local`より優先される。不要な設定は起動前に解除する。

ターミナル2（同じルート）：

```sh
npm run dev
```

[localhost:5173](http://localhost:5173/)を開く。別の作業が5173を使っている場合は、その作業を動かしたまま`npm run dev -- --port 5174`で起動し、[localhost:5174](http://localhost:5174/)を開く。ブラウザではFirebaseの許可ドメインに合わせて`localhost`を使う。

Viteの開発サーバーとローカルのpreviewは、`/api`へのリクエストを `127.0.0.1:8787` に転送する。ビルド済みのプレビュー画面は公開問題を取得せず、Hostingの配信設定はこの転送を使わない。設定を変更したらViteを再起動する。終了は両ターミナルで **Ctrl+C**。

## 期待する動作

- ログインなしで公開問題を選び、地域で絞り込める。
- 通信失敗・不正な返却・10秒の応答待ち超過では取得失敗と再試行を表示する。読み込み中や0件でも「自分の記録」を開ける。
- Googleログイン後やログイン状態の復元後に、最新のID tokenで`GET /api/v1/session`を呼ぶ。応答のuidが現在のFirebase利用者のuidと一致した場合だけ「ログインを確認しました」と表示する。uid・token・SDKエラーは画面やログへ出さない。
- 認証確認で401/503、不正な応答、uidの不一致、通信失敗が起きた場合は、選んだ問題を保持し、確認をやり直す操作を表示する。Googleのポップアップは自動で開き直さない。
- 「挑戦を始める」で最新tokenと公開問題ID・版を開始APIへ渡す。一致する応答を得てからカメラを開く。開始待ちは取消・10秒での打ち切りに対応し、409は問題の読み直し、429はRetry-After後の手動再試行を案内する。
- ログアウト・利用者変更・画面終了時は進行中の通信を中止し、古い応答を反映しない。

認証確認後は撮影、写真と位置の開発用受付、受付状態の照会を試せる。回答からの写真判定・クリア確定・記録保存は未接続。[撮影とデモ送信の手順](camera-preview.md#ローカルapiで回答を送る)

追加の開発用設定で、本人の合成記録や、自治体の下書きから合成試験・公開・休止までを試せる。[合成記録の設定](owner-discoveries.md#合成記録で一覧写真削除を試す)・[管理画面の設定](admin-demo.md#開発用の所属問題報告を閲覧する)

## 確認

```sh
npm run check
npm --prefix server run check
```

接続のテストはHTTP応答とAuthClientを明示的に代替し、問題取得、拒否・再試行、uid不一致、利用者変更後の古い結果の破棄を確認する。サーバー側は実SDKによる不正tokenの拒否も確認する。単体テストの成功を実Google ID tokenの正常系成功として扱わない。

実Googleアカウントでの開始API正常系と撮影入口は[撮影画面の確認記録](camera-preview.md#検証と残件)を参照。APIの挑戦はメモリ上の開発用データで、再起動で消える。

インストール時に見つかったサーバー依存のmoderate警告6件は、直接依存の版を維持する`npm --prefix server audit fix --ignore-scripts`で対象外の依存構成へ更新し、0件になったことを確認した。`google-gax`は5.0.8から5.0.4、`gcp-metadata`は8.1.4から8.1.2へ解決し、対象のglob/minimatch系を含む不要な依存を除去した。lockfileを共有し、各自が別々の版に更新しない。

初期の接続確認では、ブラウザからの問題取得、API停止時のエラー、再起動後の再試行での復帰、375px・320px幅の横はみ出しなしを確認した。当時の型・lint・画面105テスト・サーバー55テスト・両ビルドも成功した。

2026-11-05に実Chromeと実Googleアカウントで、Googleログイン→Firebase ID tokenのサーバー検証→現在の利用者とのuid一致を確認し、「ログインを確認しました」の表示まで成功した。再読み込み後の認証復元とサーバーでの再確認、ログアウト後の匿名表示への復帰、ログイン前後とログアウト後に同じ問題を表示できることも確認した。Auth Emulatorや代替のAuthClient・HTTP応答は使っていない。確認後はログアウト済み。アカウント名・メール・uid・token・実設定値は共有資料へ記録しない。

実スマートフォンでの操作は未検証。失効確認、組織認可、実Maps、写真判定・保存はこの確認に含まない。
