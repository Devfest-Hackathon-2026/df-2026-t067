# 決定事項・提案・未決事項

更新: 2026-11-05 / v0.3。ここまでの会話をチームの参照可能な記録へ移す。**確定**はユーザーが選んだ方針、**提案**は今回の初稿の実装案、**要確認**は本番値や運営判断が必要なもの。

## 1. 確定した製品・開発方針

| ID | 決定 |
|---|---|
| D-01 | 謎をきっかけに観光スポットへ足を運んでもらう。記録収集や再訪を主目的にしない。 |
| D-02 | 一つの全国地図から自由に問題を選ぶ。自治体別アプリ・参加イベント・固定コースを主軸にしない。 |
| D-03 | 登録・出題は地方自治体の担当者向け。一般旅行者投稿とクリアによる投稿解放は廃止。 |
| D-04 | 観光名所そのものを文章・部分写真のヒントから特定し、現地で写真回答する。難解な暗号や細部観察を必須にしない。 |
| D-05 | GPSの距離条件と写真の対象一致を両方満たしてクリアする。撮影できる場所を別に設定する。 |
| D-06 | 地図・問題・ヒントはログイン不要。挑戦開始時にログインする方式A。 |
| D-07 | 初期の旅行者ログインはGoogleアカウント。毎問題での再ログインは不要。 |
| D-08 | 自分の写真と初回クリア日を記録。再訪の写真・日付追加を初期版で作り込まない。 |
| D-09 | 天候機能、一般投稿、ランキング、再訪報酬を初期版から除外。 |
| D-10 | 既存のDevfest-Hackathon-2026/df-2026-t067で開発・共有する。新リポジトリは作らない。 |
| D-11 | 4人共通のREADME・AGENTS・docsを先に置き、ブランチとPRで改善する。個人別の仕様書は作らない。 |
| D-12 | 資料PR #1の範囲は資料作成とPRまで。その後の依頼により最小Webアプリの土台を別ブランチで追加する。mainへの取り込み、クラウド設定は別の作業。 |

## 2. 初期設計としての提案

| ID | 提案・理由 |
|---|---|
| P-01 | React/TypeScript/Vite＋Firebase＋Maps。React/TypeScript/Viteとnpmは最小Webアプリの実装判断として採用し、版を固定した。Firebase Auth SDKをGoogleログインに追加。Mapsとアプリのサーバー接続は未実装。残る構成は提案のまま。 |
| P-02 | AIはサーバーからGoogle Cloud側のGemini（Vertex AI経由を第一候補）。クレジット適用は未確認。 |
| P-03 | 未クリアは探索エリア単位のマーカー。通常レスポンスに正解を含めず、最後の明示ヒントでは対象名・撮影案内を開ける。 |
| P-04 | 自治体は招待・所属確認。編集と公開の役割を分け、初期は同一人の兼任も可。 |
| P-05 | 初期は1対象1公開問題、本人の発見はuid＋placeIdで一意。再回答で初回写真・日時を上書きしない。 |
| P-06 | 全国の器に確認済みの少数スポットを載せる。まず1問の一周、続けて3件程度で実地試験。 |
| P-07 | API経由でアプリデータを扱い、DB/Storageは既定拒否。写真送信はmultipartを第一案にする。 |
| P-08 | 保存はUTC、画面の日付はAsia/Tokyo。個人記録は本人だけに見せる。 |

提案は実装時にレビューし、変更する場合は理由と影響を記録する。採用済みクラウド設定や、性能の実測値を意味しない。

## 4. 旧案との違い

一般ユーザーが1問クリア後に投稿する案、投稿者の解答数を信用点にする案、天候推薦、自治体ごとの独立ラリー、ログイン後付けの匿名プレイ案は採用しない。過去の添付資料にこれらがあっても、本リポジトリの最新仕様に戻す。

過去の「仕様v0.2」でGoogleログインが未決だった箇所はD-07で更新済み。クラウド案v0.1は実設定ではなく、本資料でもクレジット適用・モデル・予算は未確認のまま。
