# 開発用GPS範囲判定

[回答受付API](answer-intake.md)へ、範囲・精度・撮影/測位時刻の検査を追加した。位置条件の通過だけで写真の正解やクリアを確定しない。実地点・写真・AI・保存・画面からの送信は未接続。

## 有効化

未設定または`QUEST_LOCATION_MODE=off`では従来の受付だけを維持する。GPS判定を試す場合はAPIを次の設定で起動する。Webの設定ではなく、サーバー側だけのフラグ。

```sh
QUEST_DATA_MODE=demo QUEST_LOCATION_MODE=demo NODE_ENV=development npm run dev:api
```

`npm run dev:api`は既存の`.env.local`からFirebase設定を読み、実設定をGitへ入れない。Firebase未設定では認証が503となる。実Google tokenを使った写真/GPS送信は今回未検証で、画面の送信操作もまだ追加していない。公開WebのHostingへこのローカルAPIをデプロイする操作ではない。

未知・空文字のモードは起動時に拒否する。本番・Auth Emulatorを拒否する既存のガードは維持する。起動ログはGPS demoの有効/無効だけを表示し、地点・精度・時刻・画像・tokenを出さない。

## 開発用の設定

`server/src/demo-location.ts`は既定の架空3問題の版1へ、合成した中心0,0の円を返す。管理APIから開発用に公開した問題では、サーバーがその公開版へ固定した非公開の範囲を使う。[開発用の公開と休止](api.md#18-開発用の公開と休止)

| 項目 | 試作用の値 |
|---|---|
| 既定の架空3問題の撮影半径 | 100m |
| 許容するaccuracyMetersの上限 | 50m |
| 撮影・測位それぞれの最大経過 | 120秒 |
| サーバー時計に対する未来の許容 | 5秒 |
| 撮影時刻と測位時刻の最大差 | 前後どちらも30秒 |

これらは**開発用の固定サンプル**で、本番のO-03を確定しない。実運用ではサーバーの問題ID・版に対応する非公開の設定から読み込む必要がある。`LocationValidation.policyFor`が未設定を返す、範囲が空、数値やサーバー時刻が不正なら503 SYSTEM_ERROR。誤設定を範囲外や位置不確実に隠さない。

## 分類

入力の項目・緯度経度・精度・UTC時刻は既存のCaptureMetadata検証を使い、不正なら400 INVALID_INPUT。設定と時計はサーバー側で渡す。精度の上限超過、撮影/測位の古さ・未来、両時刻の差が過大な場合はLOCATION_UNCERTAINとなる。PR #15の写真を先に固定して後から測位する順序を許容し、逆の順序でも同じ時間差を検査する。

距離d、精度a、半径rを使い、d+a <= rなら範囲内、d-a > rなら範囲外、それ以外は位置不確実。複数範囲は1つでも範囲内なら通過、全て範囲外なら範囲外、残りは不確実となる。範囲を自動で広げない。

距離は平均半径6371008.8mの球面近似と[Haversineの式](https://www.movable-type.co.uk/scripts/latlong.html)を使用し、日付変更線・極・対蹠点の丸めを扱う。[Geolocationのaccuracyやtimestamp](https://www.w3.org/TR/geolocation/)は端末からの申告値であり、この計算は訪問・位置偽装防止・安全な撮影場所・確率的な保証を与えるものではない。現地での閾値調整は未実施。

| 結果 | HTTP / AttemptResult | 次の操作 |
|---|---|---|
| 範囲外 | 200 / COMPLETED・OUTSIDE_AREA・source:mock | MOVE_TO_AREA |
| 境界・精度・時刻が不確実 | 200 / COMPLETED・LOCATION_UNCERTAIN・source:mock | RETAKE |
| 位置条件を通過 | 202 / RECEIVED・outcome:null・source:mock | WAIT（写真判定workerは未接続） |

通過は正解ではない。RECEIVEDから自動進行せず、写真は保持しない。クライアントはこれを判定中・保存済みの画面へつながない。実際の送信/結果画面の接続はC担当との後続作業。

## 再送と公開範囲

同じ本人・挑戦・キー・入力hashの再送は、時計や設定を再評価する前に元の結果を返す。後から時刻が古くなったり設定取得に障害が出たりしても、同じ回答の結果を変更しない。別キーなら新規回答として現在の条件で検査する。同じキーの別内容は従来どおり409 IDEMPOTENCY_CONFLICT。公開状態・版と所有者の確認も維持する。

共通clientは明示的demoとdemoヘッダーの場合だけ、従来の受付に加えて上表の2つのGPS不合格と対応するnextActionを許可する。既定のmock拒否、mock正解・保存・その他完了結果の拒否は維持する。

応答は受付IDと状態・結果・次操作だけ。中心・半径・距離・精度・入力位置・時刻・ポリシーを公開GET/回答結果/ログへ出さず、受付ストアにも保持しない。位置の情報は入力から評価関数へ一時的に渡すだけで、写真や位置情報を保存・外部送信しない。
