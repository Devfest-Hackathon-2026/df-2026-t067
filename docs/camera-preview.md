# 撮影・写真確認の現在の範囲

PR #9・#13〜#15のT04/T05の一部。ログインした利用者が自分の端末で撮影し、写真を確認・撮り直すための画面を追加した。撮影時のGPS情報・測位時刻・撮影時刻を写真と画面内だけで保持する。写真とGPSの送信、AI判定、クリア確定、記録保存はまだ行わない。写真は画面内の一時的なBlob URLで表示し、ネットワークへ送らず、終了時に解放する。

## 操作

1. 架空の問題を開き、Googleログインする。`local-api`モードでは、サーバーでのuid一致の確認も必要。
2. 写真を送信・保存しない説明を読み、`preview`モードなら「撮影を始める」を押す。`local-api`モードなら「挑戦を始める」を押し、[開始API](challenge-start.md)が成功してからカメラを要求する。音声は要求しない。
3. 映像が準備できたら「撮影する」でその瞬間の映像と撮影時刻を固定し、その後に現在地を1回取得する。GPS取得中も写真を確認でき、取得に失敗した場合は同じ写真のまま「位置情報を再試行」を選べる。「撮り直す」で写真からやり直すか、「撮影を終了」で破棄する。

カメラ非対応・許可拒否・起動失敗・写真作成失敗では、日本語のエラーと再試行・終了の操作を表示する。元のSDKエラーや機器情報は画面へ出さない。

`local-api`の開始待ちはキャンセルでき、10秒で打ち切る。ログイン後・画面再表示時に自動で開始しない。版変更なら「問題を読み直す」で公開問題を再取得してから改めて開始する。429はRetry-Afterの待ち時間を表示し、その後の明示操作だけで再試行する。取消・問題終了・利用者変更・ページ終了後の遅い応答ではカメラを起動しない。

APIが返した問題ID・版も選択中の公開問題と照合する。初回201と再利用200を受け付け、挑戦IDは部品の状態に保持する。ID・日時・tokenは画面やログへ出さない。「撮影を終了」後は開始済み表示を残し、「撮影を再開」で開始APIを再確認する。同じ利用者・問題・版はサーバーの一時挑戦を再利用する。`preview`モードでは開始APIを呼ばない。

問題を閉じる、地図へ戻る、ログアウト、利用者変更、ページ終了でカメラを停止する。許可待ち中に終了した場合、後から渡されたstreamも停止する。写真作成待ち中に終了した場合は遅い結果を破棄し、Blob URLを作成しない。撮り直しと終了では以前のURLを解放する。

## 撮影時の位置情報

写真と有効な位置情報が揃った場合だけ「撮影地を地図で見る（OpenStreetMap）」リンクを表示する。リンクを開くと座標がOpenStreetMapへ送られることを画面で案内し、クリック前には地図を埋め込まず外部送信しない。写真や認証tokenはリンクへ渡さない。外部ページは別タブで開き、参照元を送らない。位置未取得・取得失敗・撮り直しでは以前のリンクを表示しない。実端末GPSと外部地図を開く操作は未検証。

閲覧・カメラ起動だけでは位置情報を要求しない。「撮影する」の明示操作で映像を固定してから、高精度・キャッシュなし・取得待ち15秒の指定で1回だけ要求する。位置情報の追跡や自動再試行は行わない。写真・位置情報を送信・保存しないことを取得前に案内し、画面には座標を出さず取得精度だけを表示する。位置情報だけの再試行では写真と元の撮影時刻を保持し、映像を再撮影しない。撮り直すと以前の写真・位置情報を破棄し、次の撮影で新たに測位する。

許可拒否、取得失敗、時間切れ、非対応、API例外でも作成済みの写真は保持し、位置情報の再試行・撮り直し・終了を選べる。写真作成の失敗・撮り直し・撮影終了・ページ破棄後に届く古い位置情報は無視する。緯度経度・精度・時刻は既存の`CaptureMetadata`検証を再利用し、NaN・無限・範囲外座標・負の精度・不正時刻を写真に紐づけない。撮影範囲や鮮度・精度の本番閾値はO-03で未決のままで、サーバーによる訪問・正解判定を代行しない。将来の回答受付では元の撮影時刻と測位時刻を別々に検証する必要がある。
