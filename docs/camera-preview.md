# 撮影・写真確認の現在の範囲

T04/T05では、ログインした利用者が自分の端末で撮影し、写真を確認したり撮り直したりできる。撮影時のGPS情報、測位時刻、撮影時刻は写真と一緒に保持する。写真を表示するBlob URLは一時的に作り、終了時に解放する。`local-api`モードで送信操作を行うと、開発用APIの受付と位置判定を試せる。

## 操作

1. 架空の問題を開き、Googleログインする。`local-api`モードでは、サーバーでのuid一致の確認も必要。
2. 写真と位置の扱いを確認し、`preview`モードなら「撮影を始める」を押す。`local-api`モードなら「挑戦を始める」を押し、[開始API](challenge-start.md)が成功してからカメラを要求する。音声は要求しない。
3. 映像が表示されたら「撮影する」を押す。その瞬間の映像と撮影時刻を記録した後、現在地を1回取得する。GPSの取得中も写真を確認できる。取得に失敗したときは、写真を変えずに「位置情報を再試行」を押せる。写真を変える場合は「撮り直す」、写真を破棄する場合は「撮影を終了」を選ぶ。

カメラ映像と写真確認は、ブラウザが返す映像の縦横比を保って画面内に表示する。スマートフォンを回転すると画面向きに合わせて収まり方が変わり、撮影画像は映像フレームの幅・高さを使う。映像を余分に回転・反転しないため、向きの調整はブラウザとカメラが返すフレームに任せる。

カメラ非対応・許可拒否・起動失敗・写真作成失敗では、日本語のエラーと再試行・終了の操作を表示する。元のSDKエラーや機器情報は画面へ出さない。

`local-api`モードでは、開始APIの応答を待っている間にキャンセルできる。待ち時間は10秒まで。ログインや画面の再表示だけで挑戦を自動開始することはない。

問題の版が変わったときは「問題を読み直す」で公開問題を取得し直してから、改めて開始する。429の場合はRetry-Afterに従って待ち時間を表示し、時間が過ぎてからの再試行操作を受け付ける。取り消した後、問題やページを閉じた後、利用者が変わった後に応答が届いてもカメラは起動しない。

APIが返した問題ID・版も選択中の公開問題と照合する。初回201と再利用200を受け付け、挑戦IDは部品の状態に保持する。ID・日時・tokenは画面やログへ出さない。「撮影を終了」後は開始済み表示を残し、「撮影を再開」で開始APIを再確認する。同じ利用者・問題・版はサーバーの一時挑戦を再利用する。`preview`モードでは開始APIを呼ばない。

問題を閉じる、地図へ戻る、ログアウト、利用者変更、ページ終了でカメラを停止する。許可待ち中に終了した場合、後から渡されたstreamも停止する。写真作成待ち中に終了した場合は遅い結果を破棄し、Blob URLを作成しない。撮り直しと終了では以前のURLを解放する。

## 撮影時の位置情報

写真と有効な位置情報が揃った場合だけ「撮影地を地図で見る（Googleマップ）」リンクを表示する。リンクを開くと座標がGoogleマップへ送られることを画面で案内し、クリック前には地図を埋め込まず外部送信しない。写真や認証tokenはリンクへ渡さない。外部ページは別タブで開き、参照元を送らない。位置未取得・取得失敗・撮り直しでは以前のリンクを表示しない。実端末GPSと外部地図を開く操作は未検証。

PR #38のリンクは[Google Maps URLsのSearch形式](https://developers.google.com/maps/documentation/urls/get-started#search)を使う。main `38f3e6b`（PR #37まで）との一時統合で`npm run check`を実行し、23ファイル266テスト・型/lint/buildが成功した。写真/位置の待機・拒否・撮り直しの既存操作も維持する。サーバー・共有型・依存に変更はなく、サーバーはPR #37の188件・型/lint/build成功を再利用した。第三者であるAが差分を確認し、リンク先と送信案内に重大な指摘なし。実Googleマップの起動・実スマホ/GPSは未検証。

閲覧・カメラ起動だけでは位置情報を要求しない。「撮影する」の明示操作で映像を固定してから、高精度・キャッシュなし・取得待ち15秒の指定で1回だけ要求する。位置情報の追跡や自動再試行は行わない。送信の有無と送信先を取得前に案内し、画面には座標を出さず取得精度だけを表示する。位置情報だけの再試行では写真と元の撮影時刻を保持し、映像を再撮影しない。撮り直すと以前の写真・位置情報を破棄し、次の撮影で新たに測位する。

## ローカルAPIで回答を送る

写真と測位が揃ったら「写真と位置をデモ送信」を押す。開発用APIの受付済み、撮影範囲外、位置を確認できない場合を画面で区別する。通信が途切れた場合は同じ写真と位置で再送し、受付IDが分かっていれば「受付状態を確認」で本人照会する。写真を撮り直すと新しい回答キーを作る。操作は10秒で打ち切り、キャンセルや画面離脱でも中止する。[回答受付と再送の扱い](answer-intake.md)

許可拒否、取得失敗、時間切れ、非対応、API例外でも作成済みの写真は保持し、位置情報の再試行・撮り直し・終了を選べる。写真作成の失敗・撮り直し・撮影終了・ページ破棄後に届く古い位置情報は無視する。緯度経度・精度・時刻は既存の`CaptureMetadata`検証を再利用し、NaN・無限・範囲外座標・負の精度・不正時刻を写真に紐づけない。撮影範囲や鮮度・精度の本番閾値はO-03で未決のままで、サーバーによる訪問・正解判定を代行しない。将来の回答受付では元の撮影時刻と測位時刻を別々に検証する必要がある。
