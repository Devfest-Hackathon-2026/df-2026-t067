# 最小Webアプリの土台

## 目的・今回の範囲

4人が同じ手順で起動・検証できる入口を作る。[要求仕様](requirements.md)の全機能を今回完成させるものではない。

- 今回の実装判断としてReact・TypeScript・Viteとnpmを採用する。画面と開発ツールだけを用意し、Firebase SDKの追加・接続は次の作業にする。
- 既に導入されているNode 26.7.0 / npm 11.19.0を共通の検証版に固定する。依存パッケージは正確な版と`package-lock.json`で揃える。
- 日本語の起動画面に、全国地図を入口にする構想と開発中であることを表示する。架空の問題1件をログインなしで開閉できる。
- 挑戦開始は無効にする。ログイン・GPS・写真判定・保存の成功を模擬しない。起動時に外部APIを呼ばず、端末の権限も要求しない。
- 全国地図、Googleログイン、問題の引き継ぎ、撮影、サーバー、権限、記録保存は後続の実装範囲。クラウド管理、課金操作、デプロイはこの作業に含めない。

静的なHTMLだけでは後続のReact画面につながらず、Firebaseまで一度に接続すると未完了の管理設定と作業が重なるため、今回は画面の土台を先に作る。クラウドの採用・本番設定を確定したとは扱わない。

## 実装・完了条件

- [x] `package.json`、ロックファイル、`.nvmrc`、`.npmrc`、TypeScript・Vite・Oxlint設定を用意する。Oxlintは公式Viteひな形の静的検査ツール。既存のREADME後半、LICENSE、`.gitignore`の既存ルールを保持する。
- [x] `src/App.tsx`、`src/App.css`、`src/main.tsx`を入口にする。架空の表示用データは`src/features/quests/`に置き、実API契約の型を先回りして確定しない。
- [x] 未接続の状態で匿名閲覧でき、架空問題の開閉後も挑戦開始が無効であることを自動テストする。検証中の通信や端末権限の要求も失敗として検出する。
- [x] `npm ci`で再現でき、`npm run check`で型検査・lint・テスト・ビルドが全て成功する。ローカルブラウザでPC・スマートフォン幅の表示と問題の開閉を確認する。
- [x] READMEと`docs/development.md`に実在する起動・検証コマンド、編集場所、未実装の範囲を記載する。`.env.example`は接続しない空の設定例にする。
- [x] 差分を単独レビューし、資料PR #1に重ねた別ブランチ`codex/feat/web-foundation`で実装する。mainへの直接push・マージは行わない。

## 確認する境界

認証設定がない状態、問題を閉じて再表示した状態、キーボード操作、狭い画面、ビルド後も未接続が明示される状態を確認する。架空問題には実在地点の正解・座標・写真や本人の情報を入れない。

## 検証記録（2026-11-05）

macOS、Node 26.7.0、npm 11.19.0で確認した。

- `npm ci --offline --cache /private/tmp/tourism-quest-npm-cache --no-audit --no-fund`：ロックから再インストール成功。初回の部品取得にはネット接続を使用した。

- `npm run dev` / `npm run preview`：ローカルの起動・ビルド後表示を確認。ブラウザの1280px幅と375px幅で表示・問題開閉・無効な挑戦ボタンを確認した。
- 運営READMEの原文、LICENSE、既存`.gitignore`の一致、Markdownの相対リンク、依存の固定、公開対象ファイルを確認した。追加の単独レビューで未対応の指摘なし。

Firebase・Maps・Google認証・GPS・カメラ・AI・保存の実接続、スマートフォン実機、他メンバーのPC・他OSは未検証。4人全員の端末での起動確認は各メンバーがこの手順で行う。
