# 挑戦開始と撮影画面の接続

PR #11をレビュー・マージ後の次のA担当作業。公開APIから得た問題ID・版を保持し、`local-api`モードでは開始APIに成功した後だけカメラを開く。既存のGoogle認証・公開閲覧・端末内の写真確認を維持する。

## 完了条件

- [x] 公開問題のDTOを画面用データに保持し、開始時に選択中のID・版を共通clientへ渡す。
- [x] 開始は明示操作だけ。待機中の連打・取消・10秒超過・問題終了・利用者変更で古い応答やカメラ起動を残さない。
- [x] 401/通信失敗を安全な文言で案内し、版変更は問題を読み直せる。429はRetry-Afterを待ってから明示的に再試行する。
- [x] 応答の問題ID・版も照合し、初回201と再利用200の両方を受け付ける。IDやtokenをUI・ログへ出さない。
- [x] previewモードは従来の端末内カメラ確認だけを維持し、開始APIへ書き込まない。
- [x] テスト・型・lint・buildと、実Googleアカウントからの開始API→撮影入口を確認する。成果物は別PRで共有する。

新しいCloud設定、保存の永続化、写真・GPSの送信、AI判定、クリア確定は追加しない。APIは引き続き開発用の一時管理で、再起動時に消える。実カメラ映像・写真を確認用ログや共有資料へ保存しない。

## 検証の根拠

`ChallengeCapture.test.tsx`と`AppApi.test.tsx`で開始・エラー・取消・版変更後の再取得・古い応答の破棄を確認し、既存のpreview/auth/cameraテストも維持する。実Googleによるローカル開始と撮影入口は`docs/camera-preview.md`に記録。サーバー実装はPR #11の検証結果（69テスト、型・lint・build）を再利用し、このPRでは変更しない。
