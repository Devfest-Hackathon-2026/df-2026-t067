# 旅行者向けUI整理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans。親はUI、別worktreeの実行役はserverのみを担当する。

**Goal:** 「すっきりした旅行アプリ」というユーザーの選択に沿い、地図から謎を選ぶ入口を中心にする。

**Architecture:** 認証状態とログイン処理は既存のAuthClientを維持する。地図プレビューを分離し、デスクトップは地図と問題カード、スマホは地図と下部カード・ナビの構成にする。

**Tech Stack:** 既存React / TypeScript / CSS。地図は公開地形データから作る静的SVGで、Google Maps接続とは区別する。

**Spec:** docs/screens.mdのT01/T02/T03、既存の閲覧・認証・架空データの境界。

## Global Constraints

- 未ログインで閲覧でき、認証後も同じ問題を保持する。
- 認証処理・共通型・サーバーは変更しない。実設定をGitへ入れない。
- デモ地図・架空の1問を明記し、実際のスポットや地図APIの接続成功を示さない。
- 準備中の記録等は無効状態を明示し、動いたように見せない。

## Review Focus

- 320px幅でも地図・カード・操作・認証フィードバックが読める。
- 既存のログイン成功・取消・失敗・ログアウト・状態復元を保つ。
- マーカーと問題カードのどちらからでも同じ問題へ進める。
- 地図の拡大・縮小・初期表示へ戻す操作がキーボードで使える。
- GPS・カメラ・新しい地図APIを閲覧時に呼ばない。

## 実行記録

- ユーザーは「すっきりした旅行アプリ」を選択。A側は別worktreeで並行実装。
- Ruling: Google Mapsのキーや課金APIを使わず、Natural Earthの公開地形を使った明示的なデザインプレビューにする。実地図接続はB担当との後続作業。
- 新規の地図テスト3件の失敗を確認後に実装し、最終の`npm run check`は型・lint・86テスト・buildが成功。
- IABの1440px・375px・320px幅で確認。地図選択時のスクロールをカード先頭に合わせ、拡大・復元と横はみ出しなしを確認。実機での操作・実Google認証の再確認は今回未実施。
- 認証処理・共通API・依存ロックの変更なし。未実装の記録・撮影を成功扱いしないこと、実設定と正解データを差分へ含めないことをレビューした。
