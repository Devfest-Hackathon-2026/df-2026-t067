# ローカルAPI接続

## 目的と判断

PR #6/#7をマージした次のA担当作業として、既存の1問の画面とローカルAPI・Firebase認証確認を接続する。クラウドの追加設定や本番公開を必要としない小さな接続確認に絞る。

実MapsやDBの接続には未確定のクラウド設定があるため、今回は明示した開発用モードで`demo-quest`の1問を読む。既定の画面内プレビューは通信しない。API失敗時のサンプルへの自動切り替えはしない。

## 変更と完了条件

- [x] 共通clientに`SessionIdentity`と`getSession`を追加。最新tokenを使い、返却uidだけを境界検証する。
- [x] 開発時の同一origin proxyとAPI起動コマンドを追加。実値は`.env.local`だけに置く。
- [x] 1問の取得・読込中・取得失敗・再試行を接続。APIのデモ識別ヘッダーを確認し、本番ビルドではAPIデモを拒否する。
- [x] ログイン後にサーバーのuidを確認し、不一致・認証失敗・未設定・通信失敗を成功扱いしない。ログアウトやユーザー変更後の古い応答を破棄する。
- [x] インストール時に見つかったサーバー依存のmoderate警告を、直接依存の固定版を保った対象外の依存構成で解消・再検証する。
- [x] 型・lint・単体テスト・build、ローカルAPI接続と停止時のブラウザ確認、設定手順を揃えてPR用の差分を整理する。

認証処理そのもの、正解判定、写真、GPS、記録保存、組織権限、課金・IAM・API有効化・デプロイは追加しない。既存の認証成功・取消・復元と未ログイン閲覧を保つ。実Google tokenの正常系を試さなかった場合は未検証として記す。
