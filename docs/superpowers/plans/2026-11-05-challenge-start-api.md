# 挑戦開始API

## 目的と範囲

実カメラ確認後のA担当作業。既存の`POST /api/v1/challenges`契約を実装し、検証済み利用者と公開問題・版をサーバーで結び付ける。共通のChallenge DTO/clientを再利用する。

現在のサーバーは明示した開発用デモだけで動くため、保存先も件数上限のあるプロセス内の一時領域とする。再起動で消える。Firestore等の作成、写真・GPSの送信、回答・判定・クリア保存、画面からの挑戦開始呼び出しは今回追加しない。

## 完了条件

- [x] Firebase ID tokenから利用者を確定し、未設定・不正認証を拒否する。
- [x] JSONの形式・サイズ・項目、問題ID・公開状態・版を検証し、IDとUTC日時はサーバーで生成する。
- [x] 同じ利用者・問題・版の再要求は同じ挑戦を返し、別利用者からの所有者付き取得を拒否する。
- [x] 開発用の件数上限と、正常入力の開始要求の利用者別回数制限を用意する。
- [x] 共通clientからのHTTP確認と、境界入力・重複開始・所有者分離のテストを通す。
- [x] 実装範囲、200/201・エラー、保存制限とC担当への渡し方を資料へ記録し、PR用の差分を整理する。

同じ開始要求を再利用する200応答は、応答断後の二重開始を抑えるための具体化。初回は従来の契約どおり201。新規の本番方針としてTTLや課金・保存リージョンを決めない。

## APIの検証記録

開始201と未設定503の2件が未実装で404になる失敗を確認後に実装。容量拒否の要求が回数制限領域を埋めて既存利用者の再利用を塞ぐケースも再現し、拒否した割り当てを残さないように修正した。正常系HTTPの検証器は明示した代替で、実Google tokenを使うPOST正常系は未検証。認証前のbodyを先に捨てないこと、本文切断・5秒超過後もサーバーが応答することを確認した。画面124件のチェックも成功し、ブラウザ側のソースは変更していない。

最終の`npm --prefix server run check`は69件、型・lint・ビルドも成功。実ローカルAPIをVite proxy経由で呼び、GETの405、tokenなし・実SDKで不正と判定されるtokenの401を確認した。POST正常系の実Google確認とは区別する。
